# Tailscale Tailnetアクセス対応 仕様書

- 状態: Android統合済み・実機評価用debug APKを生成（認証後の実機受け入れ試験は未実施）
- 作成日: 2026-11-04
- 対象: TrackerControl Android / 現在の master
- 目的: 広告・トラッカーの既存ブロックを維持しながら、Tailnet内の自宅PC・サーバーへ接続する

## 1. 背景と基本方針

TrackerControlが所有する単一のVpnServiceとTUNを維持し、その内側にTailscaleを組み込む。
通常のインターネット通信は既存の直接通信経路を使い、Tailnet宛てだけをTailscaleへ送る。
Tailscale公式Androidアプリとの同時起動によるVPN連結は採用しない。

広告・トラッカーの検出・ブロックは現在のDNS情報とIPベースの判定を維持する。
すべての広告の除去、アプリ内DoH・DoTの解読、TLS傍受は保証・実施しない。
DNSのアプリ帰属がグローバルである既存の制限も変更しない。

## 2. 初期リリースの範囲

### 対象

- Tailscaleの標準サービスへのブラウザ認証と、単一Tailnetへの端末登録。
- Tailnet端末のIPv4・IPv6アドレスへの接続。
- TCP・UDP通信、および到達性確認に必要なICMP/ICMPv6。
- 通常のSSH、HTTP/HTTPS、リモートデスクトップ等のIP通信。
- MagicDNSの完全修飾名と短い端末名による名前解決。
- 直接接続と、直接接続できない場合のDERP中継。
- ネットワーク切り替え、再接続、プロセス再起動からの復旧。
- 通常通信に対する既存のSecure DNS設定の維持。

### 対象外

- Exit Nodeの選択・利用・提供。
- サブネットルーター経由のLAN接続、経路の広告、アプリコネクター。
- 既存WireGuardやグローバルSOCKS5との同時利用。
- 複数アカウント、複数Tailnet切り替え、Headscale接続。
- Taildrop、Serve、Funnel、Tailscale SSHサーバーなどの追加サービス。
- TailnetからAndroid端末上の任意サービスへ接続するための受信機能。
- 新たなアプリ別・ネットワーク別ルーティング設定。

対象外の機能は上流エンジンに存在しても暗黙に有効化しない。

## 3. 通信の仕様

```text
各アプリ → Android VPN TUN → 既存のブロック判定
                                ├─ 拒否 → 破棄
                                └─ 許可 → 宛先判定
                                           ├─ Tailnet → Tailscale → 接続先端末
                                           └─ その他 → 既存の直接通信
```

### 3.1 転送と保護

- Tailscaleへの転送前に、既存のアプリ・接続単位の許可判定を適用する。
- Tailnet端末であることを理由に、既存のブロック判定を迂回しない。
- Tailnet端末へのアクセス可否は、さらにTailscale側のアクセス制御に従う。
- Tailscaleが通知する端末情報を転送先の根拠とし、未知の宛先を直接通信へフォールバックさせない。
- 認証・制御通信、接続確立、DERP通信の外向きソケットはVPNの外へ出し、自己ループを防ぐ。
- 上記の内部通信の例外を、一般アプリの通信を迂回させる仕組みに流用しない。
- 復号された返信は同じVPN TUNへ戻す。上流の受信フィルターを無効化せず、未要求の受信接続を許可しない。

### 3.2 VPNルートとアドレス

- Tailscale有効中はIPv4 `100.64.0.0/10` とIPv6 `fd7a:115c:a1e0::/48` をVPN内で捕捉する。
- この捕捉は転送許可を意味しない。既知の許可された端末と必要な内部DNSサービスだけを処理し、それ以外は破棄する。
- 再接続中・ログイン待ち・ログアウト後も、機能が有効である限り上記の捕捉を維持する。
- 既存のCGNAT常時除外をTailscale有効時だけ上書きする。無効時は従来のルートへ戻す。
- IPv6のTailnet範囲は、既存のインターネット向けIPv6ルートとは別に扱う。
- VPNの内側の送信元は端末に割り当てられたTailnetアドレスと整合させる。
- アドレス未確定・変更時は古い識別情報で送信せず、経路とエンジンの更新完了後に転送を再開する。
- 既存のIPv6設定が無効でも、Tailnet用のIPv6アドレスと経路は利用可能にする。通常通信のIPv6設定は変更しない。
- RFC1918のLAN経路、テザリング、VPN対象外アプリの既存の扱いは維持する。
- VPN対象外アプリはこの機能でもTailnetへ接続できない。UIの説明に含める。

CGNAT範囲全体を捕捉するため、同じ範囲を使う物理ネットワークのサービスとは競合し得る。
初期版は漏出防止を優先し、競合先を直接通信へ逃がす設定は追加しない。
Tailscaleを無効にすれば従来の経路へ戻ることを説明する。

### 3.3 切断時

| 状態 | Tailnet宛て | 通常通信 |
|---|---|---|
| 無効 | 従来のルートに従う | 従来どおり |
| 有効・未認証/承認待ち | 破棄 | 既存ブロックを適用して継続 |
| 接続済み | 判定後にTailscaleへ転送 | 既存ブロックを適用して継続 |
| 再接続中/鍵期限切れ/エラー | 転送不能な通信は破棄 | 既存ブロックを適用して継続 |

制御サーバーとの一時的な切断だけを理由に、上流エンジンが維持できる既存接続を強制終了しない。
TUN再作成などに伴う短時間の接続中断はあり得るが、その間も捕捉対象を直接転送しない。
TrackerControl全体の停止やAndroidによるVPN解除後の通信は、本機能の漏出防止の保証範囲外とする。

## 4. DNSの仕様

DNS振り分けは既存DoH転送より前に行い、UDP/TCPの両方に適用する。

| 問い合わせ | 処理 |
|---|---|
| エンジンが通知するTailnetのMagicDNSサフィックスに属する名前 | 組み込みTailscaleのローカルDNSへ送る |
| 短い端末名（単一ラベル） | Tailnetの検索ドメインで解決する。公開DNSへフォールバックしない |
| Tailnetアドレスの逆引き | Tailscale側で処理し、公開DNSへ送らない |
| その他の名前 | 現在の通常DNSまたはSecure DNS設定を使う |

- 名前の比較は大文字小文字・末尾ドットを正規化し、ドメイン境界を確認する。
- 実際のTailnetサフィックスを使う。すべての `.ts.net` を無条件で自分のTailnetとして扱わない。
- TailscaleのDNSが利用不能な場合、Tailnet名にはローカルで失敗応答を返す。
- MagicDNS無効のTailnetではIP指定の接続を提供し、名前解決が使えないことを表示する。
- 短い名前のLAN DNSへのフォールバックは提供しない。LANの名前解決との競合を説明する。
- 通常DNSの応答は引き続き既存のDNS記録・ブロック処理へ渡す。
- TailnetのDNS応答も既存の記録・ポリシー処理と整合させ、無条件の許可経路を作らない。
- Tailnet側のグローバルDNS上書き、任意の分割DNS設定の取り込みは初期版の対象外とする。
- アプリ独自のDoH/DoTや独自リゾルバーによる名前解決は対象外であり、MagicDNS対応を保証しない。
- 再接続、ログアウト、端末削除、Tailnet情報更新時は関連キャッシュを無効化する。
- 認証・制御サーバー等の起動時の名前解決は、Tailnet DNSに依存させない。

`100.100.100.100` と `fd7a:115c:a1e0::53` は端末ローカルのDNSサービスとして扱う。
これらを外部DNSサーバーや通常のピアとして送信しない。管理用HTTPサービスは公開しない。

## 5. 設定画面と状態遷移

設定項目は「Tailscaleを有効化」「ログイン/ログアウト」、状態、端末アドレスを基本とする。
未接続時は、再接続中・認証が必要・管理者の承認待ち・エラーを区別して表示する。
「接続済み」はエンジンが利用可能であることを示し、すべての接続先の到達性を保証しない。

1. 有効化するとTrackerControlのVPNを準備し、必要ならブラウザの認証ページを開く。
2. 認証後、端末アドレスと経路の反映を完了してからTailnet通信を開始する。
3. 回線変更時は自動復旧し、必要な場合だけユーザー操作を案内する。
4. 無効化は通信エンジンを停止するが、認証状態は保持する。
5. ログアウトはエンジンを停止し、ローカルの鍵・認証状態・端末情報を消去する。
6. ログアウトと機能の無効化を区別し、有効のままログアウトした場合は認証待ちとする。

- 初期値は無効。既存の設定・WireGuardプロファイルを変更しない。
- WireGuardまたはグローバルSOCKS5が有効なら、先に無効化する必要があることを表示する。
- 逆方向の有効化も同じ排他条件で拒否する。保存済みプロファイルは削除しない。
- Tailscale有効化中も通常通信のSecure DNSは利用可能にする。
- VPN準備が他のVPNアプリの同意を取り消すことを、有効化フローで説明する。
- ログアウトはローカル状態の削除であり、管理画面上の端末登録の削除を保証しない。

## 6. 保存・プライバシー・消費電力

- 鍵と認証状態はアプリ専用領域に保存し、OSバックアップ、設定エクスポート、共有ログから除外する。
- トークン、鍵、認証URLを通常ログに出さない。エラー表示にも機密情報を含めない。
- 有効化時にTailscaleの制御サービス・必要な中継サービスと通信することを説明する。
- 通常通信をTailscaleやDERPへ送信しない。ブロック履歴やDNS履歴をTailscaleへ追加送信しない。
- 上流エンジンのログ・診断送信・更新確認の既定値を確認し、採用する動作をPoCで記録する。
- 接続状態はイベント通知を基本とし、UI更新用の常時ポーリングを追加しない。
- 再試行はバックオフとネットワーク状態で制御する。画面消灯中の不要な監視・ポーリングを止める。
- 接続維持に必要な上流エンジンの通信は、停止による影響を確認せず一律に切らない。
- 無効化後はTailscale用スレッド・ソケット・タイマーを停止する。

## 7. 実装構成案と現行コードの根拠

以下は設計案であり、新規クラス名や橋渡しAPIの確定仕様ではない。
Tailscaleの認証・鍵更新・NAT越え・DERP処理を独自に再実装せず、公式Go実装を利用する。

| 責務 | 現行の関連箇所 | 変更方針 |
|---|---|---|
| VPNアドレス・経路・ライフサイクル | `app/src/main/java/eu/faircode/netguard/ServiceSinkhole.java`（1845–1888、1913–1935、2033–2036、2164–2224行） | Tailscaleの状態を反映。VPN所有者を一本化する |
| CGNAT等の除外 | `app/src/main/java/eu/faircode/netguard/VpnRoutes.java`（40–75、114–129行） | Tailscale用の捕捉経路を追加する |
| 許可判定と生IP転送 | `app/src/main/jni/netguard/ip.c`（815–943、960–1037行） | 既存判定後にTailnetへの転送を選択する |
| パケット橋渡し | `app/src/main/jni/netguard/netguard.c`（447–469行） | socketpair方式を参考に、Tailscale用の境界を設ける |
| 既存WireGuardの開始 | `app/src/main/java/net/kollnig/missioncontrol/wg/WgEgress.kt`（269–370行） | ライフサイクル・protectの参考とし、gotatunへの設定追加では済ませない |
| DNS転送 | `ServiceSinkhole.java`（2553–2576行） | DoHへの転送前にTailnet DNSを振り分ける |
| トンネル返信のDNS処理 | `wgbridge-rs/src/transport/ip_send.rs`（68–105行） | 既存の記録処理との整合を確認する |

行番号は作成時点の参照であり、実装時は対応する処理を再確認する。
現行ブリッジは生IPパケットの送信元を書き換えないため、Tailnetアドレスの整合が必須となる。
現行のSOCKS5はTCP CONNECT用であり、UDPを含むパケット転送の代替にしない。
既存ブリッジのDNSドメインブロック用コールバックには未実装の経路があるため、
単にコールバックを接続しただけでDNSポリシーを維持できたと判断しない。

## 8. 実装状態と残る検証

### 統合済みの機能

単一VpnServiceへのGoエンジン組み込み、Gradleからの4 ABI AAR生成、
既存ブロック判定後のパケット転送、切断中のTailnet宛て破棄、
ローカル端末情報によるMagicDNS、通常DNS/Secure DNSとの振り分け、
設定・ブラウザ認証・ログアウト・ネットワーク変更通知を実装した。
鍵と認証状態は専用のバックアップ対象外ディレクトリへ保存する。

通常IPv6が無効な場合は、Tailnet用アドレスの追加によって通常IPv6がVPN外へ
流れるのを防ぐためIPv6全体を捕捉し、Tailnet以外をネイティブ側で破棄する。
Tailscale有効時のTUN書き込みは非ブロッキングとし、混雑時はパケットを破棄する。

### 実機評価で確認する項目

- GoのAndroid向けビルド、対象ABI、Gradle連携、依存ライセンスを確認する。
- カスタムTUN/パケットI/Oと制御バックエンドを使い、二つ目のVpnServiceを作らず接続する。
- 外向きUDPだけでなく、制御・DERP用TCPソケットの保護も検証する。
- Tailnetアドレス反映、返信、MTU/PMTUD、IPv6設定との分離を確認する。
- 認証前後のTUN再構成、ファイル記述子の所有・停止順序・再起動を検証する。
- 直接接続とDERP双方でIP指定のTCP/UDP疎通を確認する。
- 上流APIの保守負担、APKサイズ、ログ送信、画面消灯時の消費を記録する。

P0で成立しなかった項目は仕様の変更点として明示する。
SOCKS5等への方式変更でUDP・IPv6・漏出防止の要件を暗黙に落とさない。

### 検証記録

ビルド、回帰テスト、エミュレーターでの確認結果と実機手順は
[testing-tailscale.md](testing-tailscale.md) に記録する。
以下の受け入れ条件は公開判定用であり、debug APKの生成だけでは合格としない。

## 9. 受け入れ条件

| ID | 検証 | 合格条件 |
|---|---|---|
| A01 | ブロックと通常通信 | 制御可能なテストドメインで、既存ブロックが有効。許可した通常通信も成功する |
| A02 | Tailnet接続 | 自宅PCへIPv4・IPv6指定でTCP/UDP接続できる。通常のSSH/HTTPSも成功する |
| A03 | 中継 | 直接接続を妨げたネットワークでDERP経由の接続が成功する |
| A04 | MagicDNS | FQDN・短い名前・逆引きを処理し、Tailnet名が公開DNSへ送られない |
| A05 | Secure DNS | 有効/無効双方で通常DNSの既存動作とブロックを維持する |
| A06 | 切断と未知の宛先 | エンジン停止、未認証、未知のTailnet宛てを物理回線へ直接送信しない |
| A07 | アクセス制御 | Tailnet側で拒否した接続が成功しない。未要求の受信接続も許可しない |
| A08 | ライフサイクル | 回線変更、プロセス再起動、認証期限切れ、端末削除後に安全な状態へ遷移する |
| A09 | 設定の互換性 | WireGuard/SOCKS5の排他、VPN対象外アプリ、IPv6設定、LAN/テザリングを検証する |
| A10 | 保存とログ | 鍵等がバックアップ・エクスポート・ログに含まれず、ログアウトでローカル状態を消去する |
| A11 | リソースと電池 | 無効化後に専用リソースを解放し、画面消灯時の不要なポーリング・再試行ループがない |

漏出の確認は物理回線側の観測または同等のテストで行い、アプリの状態表示だけを根拠にしない。
消費電力は同一端末・同一回線・同一条件で、従来版、機能無効、有効待機を比較する。
追加消費と復帰時間を記録し、公開可否の数値基準はP0の測定後に確定する。

検証コマンドは `agents/docs/build-and-test.md` に従う。
既存の `VpnRoutesTest`、ネイティブの `route_flow_test.c` / `ip_flow_policy_test.c` を参考に、
経路、状態遷移、DNS振り分け、漏出防止を検証するテストを追加する。
Java/Kotlinのコンパイル・JVMテスト・lintに加えて、C/Go/Rustを含むGitHub debug APKをビルドする。
変更したRustコードがある場合は `wgbridge-rs` で `cargo test --workspace` を実行する。
実装後は `gemini-code-review` を実施し、未追跡ファイルもレビュー対象に含める。

実機作業は `agents/docs/device-testing.md` に従う。
既存アプリの設定バックアップと機密情報の取り扱いについて必要な確認を行い、更新はインプレースで行う。
VPN有効化が現在のVPNの同意を取り消すことを事前に説明する。
