# Gemini 4レビューの検証と修正

対象: `20d4b6c11376664cfca85f270d9ac0b24b5f2a2c` を基準とするTailscale対応。
レビュー文の一部の関数名・行番号は現行実装と異なるため、実際の呼び出し経路で確認した。

| 指摘 | 検証結果 | 対応 |
|---|---|---|
| 1. TUNの非ブロッキング化で通常通信が終了 | 妥当。従来のTCP/UDP/ICMP書き込みはEAGAINをセッション終了扱いにする | パケット全体の書き込みを再試行し、POLLOUTを待つ。停止用パイプで待機を解除する。Tailscale返信用の非ブロッキング動作は維持 |
| 2. XMLインポートの排他制約漏れ | 競合を保存できる点は妥当。ただし現行の正常インポートは保護をオフにするため「enabled=trueのまま」という説明は一致しない | XML解析・型検査・排他検査を保護停止より前へ移動。競合、型違い、不正な真偽値は現在の設定を変更せず拒否。既に保存済みの競合は起動時にTailscaleを維持し、WG/SOCKSを無効化 |
| 3. TCP DNSもUDP上流へ送信 | 妥当。TCP再試行でもUDPのTC応答を繰り返す | TCP問い合わせとDoHのTCPフォールバックは上流もTCPにする。長さプレフィックス、完全なフレーム、期限、取引IDを検査。UDPはUDPのまま |
| 4. 接続通知スレッドのJNI待機と重複通知 | 通知スレッドがGoの終了ロックを待つ可能性はある。電池消費の増加や周期処理違反は実測で確認されていない | Go処理を専用ワーカーへ移し、未処理通知を集約。同じリンク情報や無関係な帯域更新は省く。画面消灯中の実際の回線変更は復旧に必要なため処理する。Goの終了ロックは維持 |
| 5. ログイン待ち残留・別スレッドのログアウト | 妥当。LIFEロックはバックエンドを保護するが、別スレッドでの操作順序までは保証しない | 無効化・エラー・接続完了・画面離脱でログイン待ちを解除。保護オフ時も同じサービスコマンドでログアウトする |
| 6. PTR競合時の非決定性 | 同じIPを複数名が持つ場合の指摘は正しい。通常のTailnetでその状態が発生する根拠は確認していない | 防御的に、正規化した名前の辞書順で最初の所有者を選ぶ。全体ソートは追加しない |

## 検証範囲

- `tun_io_test.c`: 実際に送信バッファを満杯にし、書き込み回復時のパケット保持、
  停止通知での解除、通知を消費しないこと、EINTR再試行、致命的エラーの維持を検証。
- 既存のネイティブ防御テストも実行。TCP/UDP/ICMPの書き込みは同じヘルパーを使う。
- `SettingsImportEgressTest`: 実際のXML入力で競合・型違い・不正な真偽値を拒否し、
  現在の設定とサービス状態を変更しないこと、同じ版番号でも旧競合を修復することを検証。
- `DnsProxyServerTest`: ローカルの上流DNSスタブを用い、UDPのTC応答後にTCPで
  512バイトを超える完全な回答を得ること、取引ID不一致で次のサーバーを試すことを検証。
- `TailscaleNetworkCallbackTest`: 重複抑制、DNS・検証状態変更の通知、
  エンジン処理が待機していても通知元を止めないこと、終了時の通知取消を検証。
- `TailscaleSettingsTest`: 遅れて到着した認証URLの取消、正常なブラウザ起動、
  オフライン時もサービスキューでログアウトすることを検証。
- Goの競合検出付きテスト・vetを実行。重複PTR所有者の決定性も検証。

実機でのバースト負荷、回線切り替え、消灯時の消費電力は今回測定していない。
正常な設定インポート後に保護をオフにする既存の仕様は変更していない。
XMLエクスポートにも変更はない。

## 実行結果

- JVMテスト527件、失敗・エラー0。
- ネイティブ防御テスト、Goの競合検出付きテスト、Go vetが成功。
- GitHub debug APKの作成、Android Lintが成功。Lintエラー0。
- 最新APKのSHA-256:
  `f49a911d3ceeb9ab3e8818b1ea122308d2f7ed6c140432c8b0229295e4c974c6`。

修正後の独立レビューは `gemini-code-review` のGemini 3.8 Flash（medium）で
設定インポート、DNS/Go、Androidの接続通知・認証処理、ネイティブ処理に分けて実行した。
未追跡の新規ソースとテストもレビューに含めた。
追加指摘は呼び出し元と実装に照合した。画面離脱時に解除するのは
ブラウザをまだ開いていないログイン待ちであり、開いたブラウザでの認証を取り消さない。
設定はインポート時に置換されるため、差分マージによる競合という懸念も該当しない。
SDK 36のテストはこのリポジトリのRobolectric 4.17で実行成功している。
ネイティブ部分は初回300秒で時間切れとなったが、同じ範囲の再実行で完了した。
短い書き込みを成功扱いするという指摘は、各呼び出し元が実際に
`res != len` をエラーにし、PCAPにも実際の書き込み長を記録するため該当しない。
負のファイル記述子をpollに渡すことも、無視される仕様に沿っている。
